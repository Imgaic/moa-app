## 4. 백엔드에게 물어볼 것

- 데이터 스키마. 프론트의 초안은 `docs/user-flow.md` 9장과 `src/api/`의 타입이다(가짜 데이터로 먼저 개발 중)
- 길찾기 API, 실시간 반영 방식, 게스트 인증 방식(모두 미결정)
- 홈 목록 API(`getPlans`): 내가 참여한 약속을 한 번에 주는지, 지난 약속(`past`)을 빼고 주는지, 정렬은 누가 하는지. 지금 프론트는 홈 카드에 `id`, `title`, `status`, `confirmed.startsAt`, `confirmed.place.name`, `members`(id, name, avatarUrl)만 쓴다(`src/api/plans.ts`)
- 시각의 형식과 시간대: `startsAt`을 시간대가 붙은 ISO 문자열로 주는지. 프론트는 기기 시간대로 "오늘", "내일"을 센다
- 약속 만들기 API(`createPlan`): 보내는 값은 `title`, `durationMinutes`, `dateRange`(`"YYYY-MM-DD"` 두 개), `placeMode`, `fixedPlace`다(`src/api/plans.ts`의 `NewPlan`). 돌려받는 값은 만든 약속과 초대 링크 문자열이다. 링크 형식과 만료(Q5)는 게스트 인증과 함께 정해야 한다
- 장소(`Place`)의 모양: 지금 프론트는 `id`, `name`, `address`만 쓴다. 좌표와 장소 검색 API(카카오 로컬이 후보)를 서버가 감쌀지 앱이 바로 부를지
- 로그인한 나의 정보(`getMe`): 이름과 사진을 어디서 받는지
